# Family design language

redstone and librarian are siblings. This file is the contract both repositories follow. redstone is the reference implementation; when the two disagree, redstone's `README.md`, `src/brand.c` and `src/plat_*.c` are the examples to copy. Keep this file identical in both repositories.

## README structure

Same headings, same order, in both repositories. A section that does not apply is kept with one line saying so, so the two READMEs diff cleanly.

1. Centered logo: `<p align="center"><img src="docs/logo.svg" width="160" alt="..."></p>`, then `<h1 align="center">name</h1>`
2. One-paragraph pitch: what it is, in one or two sentences
3. Second paragraph: what sets it apart; pointer to the man page ("this file is the tour")
4. Demo: `<p align="center"><img src="docs/demo.gif" alt="..." width="720"></p>`, a 15-25 s recording of real use, generated by `docs/demo.tape` with VHS (`nix shell nixpkgs#vhs -c vhs docs/demo.tape`). Both tapes share the settings block: `Set Shell bash`, `FontSize 16`, `Width 1200`, `Height 700`, `Padding 20`, `Theme "Dracula"`, `TypingSpeed 45ms`. Keep the gif under 2 MB.
5. `## Install`: Linux, Windows (winget), from source
6. `## Build`: Nix dev shell, make targets, `make gate`
7. `## Usage`: three or four commands, each with a short comment
8. `## Keybindings`
9. `## Output modes and theming`: theme file location per platform, sections, `NO_COLOR`
10. `## Parity`: redstone's `sqlite3(1)` compatibility claim; librarian keeps the heading with one line saying it does not apply
11. `## Platforms`: Linux and Windows 10 1809+, what differs, known limits
12. `## Development`: `PROJECT.md`, `docs/ARCHITECTURE.md`, `docs/development-workflow.md`
13. `## License`: one line naming the licence and pointing at `LICENSE`

Style: British spelling as in redstone, backticks for commands and paths, no emoji, no horizontal rules, no numbered sections in the README itself.

## Identity

- One Minecraft block per program, drawn as an isometric cube in half-blocks (`▀` `▄`, 24-bit colour). redstone: redstone ore. librarian: pick its own block (a bookshelf or enchanting table fits).
- Accent colour comes from the block. redstone: red. Prompt is `glyph name ❯ ` with a single-width glyph (`●` for redstone), styled from the theme.
- Theme slots, in a `[brand]` section of the theme file: `glyph`, `name`, `tagline`, `facts`. Built-in themes `default`, `dark`, `light`, `basic` all define them. No colour at call sites.
- Banner: art at left, three caption rows at right (name spaced out, tagline, facts line). Shown only interactively, never in a scripted or compat mode, and only with colour, UTF-8, truecolor and enough columns; otherwise captions alone; otherwise plain.
- Art ships as a palette-indexed bitmap in C99 source, not as an image file at run time. The README logo is an SVG generated from that same bitmap. No Mojang assets are committed.
- Config under `~/.config/<name>/`, state under `$XDG_STATE_HOME/<name>/`; on Windows `%APPDATA%\<name>\` and `%LOCALAPPDATA%\<name>\`. No fallback to old names.

## Code rules

- C99 only (`-std=c99 -Wpedantic`), strict warnings, `-Werror` in the gate.
- Everything that differs between POSIX and Windows lives behind `include/plat.h`, implemented in `src/plat_posix.c` and `src/plat_win32.c`, each guarded by `_WIN32`. No other file includes a system header for terminals, paths, processes or clocks. Copy `plat.h` as is where the needs match; extend it, do not fork it.
- `make gate` is the single definition of done.
- The theme is split into a shared engine and a per-program half. `src/theme.c` and `include/theme.h` are identical in both repositories and name no program. `include/theme_slots.h` holds `THEME_PROGRAM` (error prefix and the `<config>/<program>/theme` path), the `ThemeStyle` enum and the `StyleName` type; `src/theme_builtin.c` defines `theme_names[THEME_STYLE_COUNT]` (`{section, key}`, `{NULL, NULL}` for `THEME_RESET`) and `theme_builtins[]` (`{name, text}`, NULL-terminated, first entry `default`). Adding a slot touches only those two files.
- `.clang-tidy` is shared in spirit: same check list, `HeaderFilterRegex` anchored on the repository directory name (`'<name>/(include|src|tests)/[^/]*\.h$'`) so system headers are not reported. librarian sets `WarningsAsErrors: '*'`; redstone still has `''` and outstanding warnings, and moves to `'*'` once they are cleared.
- `plat.h` additions wanted by librarian, to be added here first and then copied: `plat_mkdir_p` (create every missing parent, replacing librarian's four copies of `mkdir_portable`) and `plat_nprocs` (online processor count, at least 1). Terminal width (`plat_term_size`) and raw console input for a REPL (`plat_raw_enter`, `plat_read_byte`, `plat_input_ready`) already exist.

## Windows

- Minimum: Windows 10 1809 (VT input and output in the console).
- Built with MinGW-w64 on a GitHub Actions Windows runner (MSYS2 UCRT64), static, vendored dependencies where there are any. Locally, `nix develop .#windows` cross-compiles and runs the tests under Wine.
- CI: `.github/workflows/ci.yml` runs `make gate` in the Nix shell on Linux plus the native Windows build and tests; `.github/workflows/release.yml` publishes `<name>-X.Y.Z-linux-x86_64.tar.gz`, `<name>-X.Y.Z-windows-x86_64.zip` and `SHA256SUMS` on a `v*` tag.
- Release is a zip with the `.exe`; a winget manifest (`ProvidenceCrafts.<name>`, portable zip) lives under `packaging/winget/<version>/`, with the per-release steps in `packaging/winget/README.md`.
- Binary files are opened in binary mode; the console runs in UTF-8.
